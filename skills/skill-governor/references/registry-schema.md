# Registry schema

`skill-roadmap.json` is human-maintained. Every route requires:

- `lane`: functional domain;
- `stage`: place in a broader workflow;
- `brief`: short capability statement;
- `use_when`: positive trigger;
- `boundary`: what belongs elsewhere;
- `role`: `primary`, `specialist`, `alternate`, `complementary` or `standalone`;
- `review_level`: `description-derived` or `full-reviewed`;
- `overlap_group`: zero or more declared comparison groups.

Routes may additionally declare `input_types` and `target_tools`. The capability
gap helper uses these as hard compatibility gates after the manager has assigned
the semantic `lane`; it does not infer semantic fit from filename keywords.

`skill-registry.json` is generated by scanning installed roots. It stores
behavior fingerprints, paths, mapping state and quality evidence. Do not copy
route data into it manually.

`skill-sources.json` records provenance, version pins, license and local changes.
`skill-usage.json` records material uses. `skill-retirements.json` is a recovery
index for disabled or merged skills.

Full gap handling produces four project-local artifacts rather than adding
conversation text to the registry: `capability-request.json`,
`routing-decision.json`, `gap-resolution.json`, and `candidate-adoption.json`.
Only accepted source, mapping or quality evidence belongs in the shared
registry.

Evidence is tied to a task ID and the exact behavior fingerprint. A changed
skill returns to provisional status until the new version earns evidence.
